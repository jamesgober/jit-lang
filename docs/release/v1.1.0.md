# jit-lang v1.1.0

Large stack frames no longer crash the host, and compiled loops can now be stopped from another thread. Upgrading needs no code change.

## Stack probes

A function with many values live across a loop spills them, and its frame can be tens of kilobytes. The prologue used to move the stack pointer down by the whole frame and then store into it without touching the pages in between. The first store could land past the guard page: an access violation on Windows, and a write into whatever was mapped below the stack on other systems.

Stack probes are now on, inline. The prologue touches the frame one page at a time, so the stack grows in order and a real overflow reaches the guard page. Inline probes call no helper function, so compiled code still needs no relocation. Running out of stack still ends the process, as it does for any native code.

The docs used to say compiled code "never faults on any input". That was only ever true of integer arithmetic, and they now say exactly that.

## Interrupting compiled code

Compiled code cannot be preempted, so a loop that never ends used to hold its thread for good. `Jit::compile_interruptible` compiles a function that checks an `Interrupt` flag at the end of every loop iteration. Once the flag is set, the function returns the zero value of its return type (`0`, `0.0`, `false`, or nothing). Check `Interrupt::is_interrupted` after the call to tell an interrupted run from a real result.

```rust
use jit_lang::{Interrupt, Jit};

let interrupt = Interrupt::new();
let f = Jit::new()?.compile_interruptible(&func, &interrupt)?;

let watchdog = interrupt.clone();
std::thread::spawn(move || {
    std::thread::sleep(std::time::Duration::from_millis(100));
    watchdog.interrupt();
});
```

The check is one byte load and one branch per loop iteration. Code with no loop never checks the flag. `Jit::compile` is unchanged.

Compile time still grows with the size of the function and is not capped by this crate. A host that accepts untrusted IR should cap function size before compiling.

## Tests

- `tests/stack.rs` runs a loop that keeps 5,000 values live (a frame of about 40 KB) on a thread with a 1 MiB stack. On 1.0.1 it crashes the test process on Windows.
- `tests/interrupt.rs` stops an infinite loop and a nested loop from another thread, stops calls on four threads with one flag, checks the zero value for each return type, and checks that loop-free code ignores the flag.
- A unit test checks that the flag is read only on loop edges.
