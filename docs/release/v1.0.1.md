# jit-lang v1.0.1 — division that cannot crash the host

**A correctness patch.** In `1.0.0`, compiled integer division could kill the process that called it. This release makes division total, fixes the Windows ARM64 instruction-cache path, and declares `bool` zero-extended across the ABI. There is no public API change; upgrading is a `cargo update`.

**Everyone on `1.0.0` should upgrade.** A function that `ir-lang` validates could, given a zero divisor or `i64::MIN / -1`, take the host process down. No error was returned and nothing could be caught.

## Division traps (ISSUES H10)

`BinOp::Div` on `int` lowered to Cranelift's `sdiv`, which traps on exactly two inputs:

| Input | 1.0.0 on x86-64 | 1.0.1 |
|---|---|---|
| `x / 0` | `ud2`: SIGILL / `STATUS_ILLEGAL_INSTRUCTION`, process dies | `0` |
| `i64::MIN / -1` | `idiv` overflow: SIGFPE / `STATUS_INTEGER_OVERFLOW`, process dies | `i64::MIN` |
| anything else | truncating quotient | the same truncating quotient |

On AArch64, whose `sdiv` instruction never faults, Cranelift added explicit trap checks for both cases. The process died there too.

### Why these values

jit-lang's frozen calling convention is a plain `extern "C" fn(..) -> T`. A compiled function has no way to return an error, so neither case can be reported as one in `1.x`. The values were chosen to match the tiers that already exist:

- **`MIN / -1 == MIN`** is `i64::wrapping_div`, the operator the bytecode tier's reference interpreter (codegen-lang) uses. It is also the same two's-complement wrap jit-lang already applies to `add`, `sub`, `mul`, and `neg`.
- **`x / 0 == 0`** is not defined by ir-lang 1.0 or by the bytecode tier. The bytecode reference interpreter panics on it, and its docs say it makes no statement about bytecode semantics. `0` is what AArch64's `sdiv` produces. It is now documented.

The tiers disagree, and this patch does not reconcile them. The LexerSketch operation spec (`OPS.md`) defaults to `div_zero = error` and `overflow = error`; the bytecode VM's 2.0 work follows it. Honoring those defaults needs an error return from compiled code. That arrives with jit-lang 2.0 on the native backend (LexerSketch Phase 5), not in a `1.x` patch.

### How

The divide is guarded without a branch:

```text
special  = (r + 1) <=u 1          // r is 0 or -1
divisor  = special ? 1 : r        // the hardware divide never sees 0 or -1
q        = sdiv l, divisor
result   = special ? l * r : q    // l*0 = 0;  l*-1 = -l, wrapping MIN to MIN
```

On x86-64 that adds a `lea`, a `cmp`, two `cmov`s, and an `imul` next to the `idiv`. Cranelift's own zero check before `idiv` is still emitted, but it can never be taken. With a constant divisor the guard folds away completely: `x / 7` becomes a multiply-high sequence, `x / 0` becomes `0`, and `x / -1` becomes `neg`.

### The rest of the audit

Cranelift's trapping instructions are `sdiv`, `srem`, `udiv`, `urem`, `fcvt_to_sint`, `fcvt_to_uint`, `trap`, `trapz`, `trapnz`, and `uadd_overflow_trap`. ir-lang 1.0 has no op that lowers to any of them except `sdiv`. A new unit test translates a function that uses every op on every operand type. It fails if any trapping instruction other than `sdiv` appears, or if an `sdiv`'s divisor is anything but the guard's `select`. Float division stays IEEE: `x / 0.0` is an infinity or NaN.

## Windows ARM64 instruction cache (ISSUES M55)

`1.0.0` flushed the instruction cache on every non-macOS AArch64 target with the compiler runtime's `__clear_cache`. MSVC's runtime does not have that symbol, so a Windows ARM64 build could not link. Windows now calls `FlushInstructionCache(GetCurrentProcess(), code, len)` from kernel32. It is declared through raw FFI, like pager-lang's `VirtualAlloc`, and adds no dependency.

**Verified:** `cargo check` and `cargo clippy -D warnings` for `aarch64-pc-windows-msvc` on stable and 1.94. **Not verified:** execution on Windows ARM64 hardware. CI has no such runner.

## `bool` ABI and `entry` size check (ISSUES M56)

- `bool` parameters and returns were plain `I8` slots, which left the upper bits of a returned `bool` register unspecified. Rust's `bool` and C's `_Bool` are `zeroext`. They are now declared `uext`.
- `Compiled::entry::<F>` checked `size_of::<F>() == size_of::<*const u8>()` only with `debug_assert!`. It is now `const { assert!(..) }`, evaluated when `entry::<F>` is instantiated, in every build profile. A wrong-sized `F` was already undefined behavior under the documented contract. It is now a compile error, and a `compile_fail` doctest shows one.

## Tests added

- **`tests/division.rs`** (9 tests + 3 properties). Covers `x / 0` for edge dividends, `MIN / -1`, `MIN rem -1`, every pair of nine edge values for both divide and remainder, constant divisors (folded guard), fully constant operands, division inside a loop with runtime divisors including `0` and `-1`, and float division by zero. Remainder is spelled `a - b * (a / b)`, since ir-lang 1.0 has no remainder op. The properties cover a single divide, the composed remainder, and random add/sub/mul/div/neg chains biased toward `0`, `±1`, `MIN`, and `MAX`.
- **Oracle.** Every case runs natively in the test process and is compared with `tests/support`, an IR interpreter replicated from codegen-lang's bytecode-tier reference. It uses the same operators, with `x / 0 == 0` added where the original is undefined.
- **Mutation check.** With the `1.0.0` lowering restored, `test_min_divided_by_negative_one_wraps_to_min` kills the test binary with `STATUS_INTEGER_OVERFLOW` and `test_divide_by_zero_returns_zero_without_trapping` kills it with `STATUS_ILLEGAL_INSTRUCTION`.
- **Unit tests.** One checks that `bool` signature slots are `uext`. One is the no-trap audit above. A workflow test passes `bool` arguments and reads a `bool` return.

## Performance

`call_guarded_div` is a new Criterion bench: one call of a compiled `fn(int, int) -> int { a / b }` with a runtime divisor. Measured on one noisy Windows x86-64 machine, alternating runs:

| Lowering | `call_guarded_div` | `call_compiled` (call floor, no divide) |
|---|---:|---:|
| 1.0.0 bare `sdiv` | 1.84–2.07 ns | 1.95–2.08 ns |
| 1.0.1 guarded | 2.54–2.88 ns | 2.06–2.70 ns |

The guard costs about 0.5–0.9 ns per runtime-divisor division. A constant divisor costs nothing extra.
