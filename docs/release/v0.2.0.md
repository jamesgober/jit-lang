# jit-lang v0.2.0 — Compile and Run

**The core release.** v0.2.0 turns jit-lang from a scaffold into a working just-in-time compiler: it lowers an `ir-lang` function to native machine code, places that code in executable memory, and hands back a function you can call. The public surface is four items — `Jit`, `Compiled`, `JitError`, and the free `compile` — and the whole path from IR to a running function is covered by tests that compile representative programs and execute the result. Zero unsafe on the way in; one documented `unsafe` method to call out.

## What is jit-lang?

jit-lang is the run-it-now end of the `-lang` language-construction family. A front-end parses, type-checks, and lowers a program to the [`ir-lang`](https://docs.rs/ir-lang) intermediate representation; jit-lang compiles that representation to machine code for the host through [Cranelift](https://cranelift.dev), writes it into a guard-flanked region from [`pager-lang`](https://docs.rs/pager-lang), flips the region to read-execute, and returns a callable handle. There is no object file and no separate linker step — the function runs in the same process that built it.

## What's new in 0.2.0

### The `Jit` engine and the `compile` shortcut

`Jit` holds a code generator configured for the host CPU, built once and reused. `Jit::compile` validates a function, translates it to Cranelift IR, generates native code, and places it in executable memory. For a single compile, the free `compile` function does the same in one call.

```rust
use jit_lang::Jit;
use ir_lang::{Builder, BinOp, Type};

let jit = Jit::new().expect("the host is supported");

// fn mul(a: int, b: int) -> int { a * b }
let mut b = Builder::new("mul", &[Type::Int, Type::Int], Type::Int);
let a = b.block_params(b.entry())[0];
let c = b.block_params(b.entry())[1];
let p = b.bin(BinOp::Mul, a, c);
b.ret(Some(p));

let mul = jit.compile(&b.finish()).expect("mul is well-formed");
```

The IR and Cranelift line up closely — both are SSA control-flow graphs whose values cross blocks as block parameters rather than through phi nodes — so the translation is mostly a relabeling. Reachable blocks are emitted in reverse postorder, so a value's definition is always generated before its uses; unreachable blocks are dropped.

### `Compiled` — the runnable result

`Compiled` owns the executable memory, so the code stays mapped for exactly as long as the handle lives. It reports the function as compiled (`name`, `params`, `ret`, `code_len`), exposes the entry pointer (`as_ptr`), and turns that pointer into a callable function with the one `unsafe` method, `entry`.

```rust
use jit_lang::compile;
use ir_lang::{Builder, BinOp, Type};

// fn double(x: int) -> int { x + x }
let mut b = Builder::new("double", &[Type::Int], Type::Int);
let x = b.block_params(b.entry())[0];
let sum = b.bin(BinOp::Add, x, x);
b.ret(Some(sum));
let f = compile(&b.finish()).unwrap();

// SAFETY: the signature is `fn(int) -> int`, and `f` outlives the call.
let double: extern "C" fn(i64) -> i64 = unsafe { f.entry() };
assert_eq!(double(21), 42);
```

The IR's four machine types map onto the host C ABI: `int` to a 64-bit integer, `float` to `f64`, `bool` to a `0`/`1` byte, and a `unit` return to no return value. The compiled code uses the host C calling convention, which is what `extern "C"` denotes, so a matching function pointer calls it correctly. A `unit`-typed *parameter* has no machine representation and is refused.

### Control flow: branches and loops

Branches and loops lower to native control flow. A loop carries its running state as block parameters on the header — the SSA stand-in for a phi node — and the back-edge passes the next iteration's values:

```rust
use jit_lang::compile;
use ir_lang::{Builder, BinOp, Type};

// fn sum_to(n: int) -> int { let mut acc = 0; while n > 0 { acc += n; n -= 1 } acc }
let mut b = Builder::new("sum_to", &[Type::Int], Type::Int);
let n0 = b.block_params(b.entry())[0];
let header = b.create_block(&[Type::Int, Type::Int]);
let body = b.create_block(&[]);
let exit = b.create_block(&[]);
let zero = b.iconst(0);
b.jump(header, &[n0, zero]);
b.switch_to(header);
let n = b.block_params(header)[0];
let acc = b.block_params(header)[1];
let z = b.iconst(0);
let more = b.bin(BinOp::Gt, n, z);
b.branch(more, body, &[], exit, &[]);
b.switch_to(body);
let acc2 = b.bin(BinOp::Add, acc, n);
let one = b.iconst(1);
let n2 = b.bin(BinOp::Sub, n, one);
b.jump(header, &[n2, acc2]);
b.switch_to(exit);
b.ret(Some(acc));

let f = compile(&b.finish()).unwrap();
// SAFETY: the signature is `fn(int) -> int`, and `f` outlives the call.
let sum_to: extern "C" fn(i64) -> i64 = unsafe { f.entry() };
assert_eq!(sum_to(100), 5050);
```

### `JitError`

A compile fails for one of four reasons, one per stage: `InvalidIr` (the function did not validate), `Unsupported` (a valid function the back-end cannot lower, or an unsupported host), `Codegen` (the code generator failed), and `Memory` (executable memory was unavailable). The enum is `#[non_exhaustive]`, implements `Display` and `std::error::Error`, and converts from the wrapped error types for `?`.

### Dependencies

Three layers, each wired where it is first used: `ir-lang` is the input IR, `cranelift-codegen` / `cranelift-frontend` / `cranelift-native` are the native code generator, and `pager-lang` provides the executable memory. The code generator sets the **MSRV to 1.94** — the one place this crate sits above the family's 1.85 baseline.

### Tests, examples, benchmarks, and `API.md`

The workflow suite compiles and **runs** `double`, `abs`, `max`, a countdown loop, float arithmetic, boolean logic, integer division, and a unit function, checking the results the CPU produced. Property tests generate random functions and compare the compiled output to an independent evaluation in Rust. Three runnable examples and a Criterion benchmark suite ship alongside, and `docs/API.md` documents every public item with worked examples.

## Breaking changes

**None at the public API.** v0.1.0 was a scaffold with no domain logic; v0.2.0 adds the first functional surface. The **MSRV moved to 1.94**, which is a compatibility note for anyone pinning an older toolchain.

## Verification

Run on Linux (WSL2 Ubuntu) x86_64, Rust stable 1.95 and the 1.94 MSRV toolchain; the same commands run on the CI matrix across Linux, macOS, and Windows.

```bash
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings
cargo clippy --all-targets --all-features -- -D warnings
cargo test
cargo test --all-features
RUSTDOCFLAGS="-D warnings" cargo doc --no-deps
cargo deny check
cargo audit
cargo +1.94 check --all-targets   # MSRV
cargo run --example jit_and_call
cargo run --example control_flow
cargo run --example floats
```

All green. Counts at this tag:

- 10 unit tests, 14 doc tests.
- 10 workflow tests, 2 property tests, 4 error-path tests.
- `cargo deny`: advisories, bans, licenses, sources all ok. `cargo audit`: no advisories.

Indicative Criterion means on this host (`cargo bench --bench bench`): a two-way branch compiles in ~27 µs, a loop in ~34 µs; calling a compiled function is ~1.4 ns — a plain indirect call into native code.
